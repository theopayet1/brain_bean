
En s&box, la visibilité du curseur est **entièrement gérée par le CSS** via `pointer-events`, pas par du C# pur.

#### Valeurs possibles :
| Valeur                    | Comportement                                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `pointer-events: none`    | Défaut — inputs vont au jeu, curseur caché(  le classique sa se déplace avec ton perso )                     |
| `pointer-events: all`     | Curseur visible, inputs vont au panel UI ( sa desactive le lien ave ton perso en gros ton curseur et libre ) |
| `pointer-events: inherit` | Hérite du parent                                                                                             |

#### Rendre un panel cliquable (ex: menu F1)
```scss
// classmenuview.razor.scss
 classmenuview { pointer-events: all; 
 } 
```


> [!warning]
> Bug connu : après avoir masqué la souris (`Mouse.Visibility = Hidden`)
> puis la réafficher (`Auto`), les panels croient qu'un bouton est encore
> enfoncé. Workaround : forcer un `MouseButtonsReleased` ou recréer le panel.
